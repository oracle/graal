Report linkage errors encountered while parsing methods of selected classes during image building.
For example, an unresolved type, field, or method causes the image build to fail instead of
deferring the corresponding linkage error until the affected code executes. Without arguments,
the option applies to all classes in its scope.

Using --link-at-build-time without arguments is only allowed on command line or when embedded in a
native-image.properties file of some zip/jar file on the module-path (but not on class-path).

On the module path, the option applies to all classes in the containing module. Without arguments
on the command line, it applies to all classes.

Using --link-at-build-time with class or package arguments is allowed in every scope:

  1. On command line
  2. Embedded in a native-image.properties file of some zip/jar file on module-path
  3. Embedded in a native-image.properties file of some zip/jar file on class-path

If the option is embedded in native-image.properties file in some zip/jar file all class-names
and package-names passed to the option have to be found in the zip/jar files the option is embedded
in. Using --link-at-build-time with arguments on command line does not have that restriction.

Using --link-at-build-time=module=<module-name> or --link-at-build-time=package=<package-name>
is only allowed on command line, not in an embedded native-image.properties file.
The package selector also accepts a trailing .* to include subpackages.
